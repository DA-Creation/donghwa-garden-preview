## 작동 범위

시작 → 음식 복수선택 → 식사·활동·수면을 포함한 5개 질문 → 생활 유형 → 내일의 실천 체크리스트 → 단백질·활동·수면 리포트 → 메뉴별 비용·영양 비교 → 구독 구성 모달. 뒤로 이동해도 답변 유지. 같은 탭을 새로고침하면 sessionStorage에서 이어간다. 다시 시작으로 답변 초기화. 리포트 저장 버튼은 가입·로그인 안내를 연다. 안내에서 기존 A안 로그인 시안으로 이동하거나 텍스트 파일로 내려받을 수 있다. 리포트 복사도 제공한다.

생활 계산은 `lifestyle.mjs`, 질문·결과 화면은 `lifestyle-ui.mjs`, 추가 스타일은 `lifestyle.css`로 분리했다. [질문 흐름과 근거](LIFESTYLE-SOURCES.md)에 공식 출처, 계산식, 적용 대상과 한계를 기록했다. 단백질 부족을 배달 메뉴 선택만으로 판정하지 않으며, 하루 전체 섭취 기록이 있을 때만 2025 한국인 영양소 섭취기준의 연령·성별 권장량과 비교한다. 활동 시간은 최근 7일 기록과 일반 성인 권장량을 비교한다. 정보 없음·개인 조절 필요 응답은 숫자를 만들어내지 않는다.

배달을 먹지 않는 응답도 같은 5개 질문으로 마친다. 배달 빈도·인분·준비 시간은 테스트에서 묻지 않는다. 비교 자료가 없는 기타 메뉴는 수치 비교에서 제외한다. 수치 비교가 가능한 메뉴를 함께 선택한 경우 해당 메뉴만 평균내며, 기타 메뉴는 유형 태그에 반영한다.

메뉴별 금액과 인분은 결과에서 수정한다. 주간 식사 수는 비교용 예시 조건으로 시작하며, 결과에서 1~3끼로 바꿀 수 있다. 준비 시간을 답하지 않았으므로 특정 조리 시간을 사용자가 원한다고 표시하지 않는다.

## 수치 상태

`model.mjs`의 음식 가격·영양·구독 가격·식수는 모두 계산을 시연하기 위한 가상 데이터다. 검증된 동화가든 상품 가격이나 영양 수치가 아니다. 결과·가격 비교·상품 모달에 표시했다. 실제 판매 전, 동일 메뉴·옵션의 공식 영양표/식약처 데이터와 실제 상품 운영값으로 교체해야 한다.

식수로 나눈 메뉴 평균을 계산하며 선택 메뉴를 합산하지 않는다. 구독은 8끼 64,000원인 예시 묶음을 필요한 개수만큼 온전히 구매하는 것으로 계산한다. 밥값 한 끼 1,000원을 추가한다. 4끼만 대체해도 한 묶음 전체를 반영하고 남는 4끼를 표시한다. 비싸지는 경우 추가 비용으로 표시한다. 4주는 한 달이라고 표현하지 않는다.

원래 사이트는 수정하지 않았으며 로그인·결제·구독 신청·외부 데이터 저장은 연결하지 않았다. 구독 상세 버튼은 실제로 열리는 기존 GitHub Pages 시안으로 연결한다.

## 검증

```powershell
node --check app.mjs
node --test model.test.mjs lifestyle.test.mjs
```

계산 테스트: 복수선택 평균, 전체 묶음 비용, 추가 구매 및 잔여 식수, 배달 없음, 비교 데이터 없음, 금액·인분 수정, 필수 선택, 저장 상태 검증.

현재 5문항 버전: 계산·질문 흐름 테스트 16개 통과. 브라우저에서 음식→식사 습관→활동량→수면→관심사의 5단계와 화면별 단일 답변 항목을 확인했다. 다섯 번째 답변 직후 결과가 표시되며, 선택 입력 없이 생활 제안과 상품 비교를 볼 수 있다. 결과의 선택 입력에서 단백질 35g/참고량 50g의 차이 15g, 활동 중강도 40분+고강도 10분 → 주 5일 20분 추가 예시가 계산되는지 확인했다. 확인 경로의 브라우저 경고·오류는 없었다.

현재 버전은 음식 취향·식사 습관·활동량 범위·수면·관심사의 실제 5개 질문이다. 질문마다 하나의 답변 항목만 있다. 상세 수치는 결과에서 선택 입력한다. `short-quiz.mjs`가 간단한 활동·수면 질문과 선택 입력 모달을 담당한다.

## 사이트 연결과 회원 저장

- A안 회의 수정본의 하단 `나의 냉장고` 메뉴를 `생활 리포트`와 리포트 SVG 아이콘으로 교체했다. `/meal-quiz/`로 이동한다.
- 테스트 시작·질문·결과 화면에도 같은 하단 메뉴를 유지한다. 진행 버튼과 메뉴는 하나의 고정 영역에 쌓으며, 실제 높이를 측정해 본문이 가려지지 않도록 한다. 상단 뒤로 화살표는 동화가든 홈으로 연결한다. 같은 탭에서 메뉴를 이동한 뒤 돌아오면 답변과 결과가 유지된다.
- `/a-meeting/?report=save#login`은 기존 로그인 시안을 열며, 리포트 저장 목적과 계정 저장 미연동 상태를 안내한다. 같은 탭에서 `내 리포트로 돌아가기`를 누르면 sessionStorage에 남긴 결과를 다시 보여준다.
- 로그인·회원가입과 마이페이지 DB 저장은 아직 구현되지 않았다. 회원 저장 성공처럼 표시하지 않으며, 현재 보관 수단은 파일 다운로드다. sessionStorage는 탭을 닫으면 사라지는 임시 상태다.
- 실제 서비스에서는 가입·로그인 완료 → 인증된 사용자 ID로 리포트 저장 → 마이페이지 조회 순서로 연결해야 한다. 답변 및 선택 건강 기록을 URL이나 공개 저장소에 넣지 않는다.
