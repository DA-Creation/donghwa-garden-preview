쿠캣 실측은 24000/1001fps, 141프레임, 5.880875초이며 내부 경계는 1.418083초(34), 4.045708초(97)다. 1.42/2.63/1.84초는 편집 설계의 반올림 값이며 합은 5.89초다.

## 2. 참조의 역할과 제품 정체성

### 현재 입력 단계의 역할 분리

1. **새 시작 이미지 제작**: [실제 제품 사진](reference/donghwa-42-actual-product.jpg)은 음식·분량·황동 그릇·색·질감의 유일한 근거다. 쿠캣의 해당 컷 시작 프레임은 구도와 수저 위치만의 참조로 사용한다. [V3 이미지 요청 기록](prompts/v3-keyframe-prompts.json)을 보존하며, 채택된 shot02 재시도는 [V4 이미지 기록](generation/keyframes-v4/shot02-manifest.json)과 잠긴 수저 입력을 따른다.
2. **시작 이미지 검수**: 동화 음식 정체성과 해당 컷의 출발 상태를 각각 확인한다. 기존 D 후보·V1의 반복 입자 이미지·V2의 경쟁사 음식은 입력으로 쓰지 않는다.
3. **각 영상 I2V**: 검수를 통과한 해당 새 이미지 하나를 첫 프레임으로 넣는다. 다음 영상 요청에 쿠캣 영상 자체를 넣지 않으며, 경쟁사 음식이 다시 따라 들어오는 경로를 줄인다.
4. **최종 편집**: 쿠캣 영상은 로컬에서 구도·동작·길이를 비교하는 근거로 사용한다. 경쟁사 프레임을 완성 영상에 끼워 넣지 않는다.

실제 사진의 출처는 프로젝트 루트 `thumbnail-generation-20261028/evidence/source-images/42-original-detail-4.jpg`다. 흰 여백과 보이는 증기는 재현하지 않는다. 동작 참조는 [쿠캣 상세본문 영상](reference/cookat-1834-detail-hero.mp4), [공식 상품 1834](https://cookatmarket.com/ko/product/detail?product_id=1834)이다. 상단 갤러리와 혼동하지 않는다.

사용자는 매우 가까운 구도 재현을 요청했고 V2에서 영상 참조 입력도 허용했다. 현재 영상 입력을 빼는 것은 사용자의 허용을 취소하는 해석이 아니라 V2의 음식 복사 실패에 따른 구현 변경이다. **경쟁사의 음식·완성 영상은 동화가든 결과로 복사·게시하지 않는다.**

### 실제 순두부와 AI 반복 패턴을 구별한다

- 실제 원본은 크기가 다양한 찢어진 부드러운 덩어리, 넓고 부드러운 깨진 면, 불완전하게 접히거나 무너진 가장자리, 작은 잔조각이 섞여 있다. 일부는 국물에 잠겨 경계가 부드럽게 이어진다.
- 원본의 미세 조각은 보존하되, 모든 덩어리를 같은 크기·간격·밝기의 구슬·쌀알·사슬·콜리플라워 돌기로 바꾸지 않는다. ‘fine crumbly’라는 말만으로 규칙적 미세 패턴을 통과시키지 않는다.
- 원본에서 부드럽거나 해상되지 않은 부분을 새로 날카롭게 묘사하지 않는다. 큰 순두부 면, 잔조각, 기존 해물, 채소와 부추는 각각 다른 표면을 유지한다.
- 반복 입자를 없애겠다고 매끈한 큐브·공·유리·젤·한 덩어리의 퓨레로 치환하지 않는다.
- 국물의 실제 붉은 주황색, 가벼운 깊이, 부드러운 부분 경계, 제한된 국소 반사를 유지한다. 음식 전체를 균일한 유광·바니시로 코팅하지 않는다.
- 식재료 이름을 사진만 보고 새로 확정하지 않는다. 실제 원본의 형태·상대량을 보존하며 새 해산물·고명·달걀·면·치즈·버섯·고기 등을 추가하지 않는다.

### 이번 버전에서 만들지 않을 것

새 김·증기·연무·연기·실 같은 수증기, 끓음·기포·거품, 국물방울·매달린 액체·액체 실·낙하·튀김·동심원 파문을 생성하지 않는다. **‘작고 자연스러운 방울’도 허용하지 않는다.** 음식은 불에서 내린 상태이며 표면은 스푼이 닿는 곳만 움직인다. 쿠캣 원본의 실제 끓음도 현재 출력에 옮기지 않는다.

## 3. 새 컷별 시작 이미지의 필수 검수

이미지 생성 완료와 입력 승인 상태를 구분한다. 이 기준표 자체는 세 장의 검수 완료를 의미하지 않으며, 직접 확인하지 않은 항목을 PASS로 표시하지 않는다. 실제 판정은 이미지별 QA 기록을 따른다. V1 이미지가 있었다는 이유로 새 검수를 생략하지 않는다.

| 컷 | 시작 이미지에서 확인할 상태 | 즉시 기각할 예 |
|---|---|---|
| 1 | 실제 황동 그릇·국물·불규칙 순두부. 우상단 나무 스푼의 낮고 작은 순두부 분량이 중앙 국물에 닿기 직전 | 달걀/두부 공, 경쟁사 회색 냄비, 높은 음식 산, 빈 금속 스푼, 매달린 액체 |
| 2 | 같은 방향의 약간 넓은 구도. 스푼 머리가 대부분 국물 아래 있고 손잡이/윗 금속 가장자리만 보임 | 공중의 빈 스푼, 들어 올리는 복귀 자세, 퍼 올릴 준비, 다른 식당/재료·새 식탁 |
| 3 | 기존 깨끗한 선택 구간은 추가 리프트가 남아야 함. 예비 입력을 쓰면 낮게 분리되어 지지된 한 입과 깨끗한 밑면/공기 틈 | 이미 높은 곳에서 정지한 음식 산, 추가 리프트 없음, 긴 경쟁사 버섯, 액체 실/방울 |

세 장의 음식·분량·그릇·색·광택과 원본 해상 수준을 나란히 비교한다. 낱알이 있다는 이유만으로 기각하지 않지만 규칙적으로 반복되고 과선명해진 구슬·쌀알·돌기는 기각한다. 새 김·기포·방울·새 재료도 입력 단계에서 제거되어야 한다.

iCloud 파일명만 보이는 상태를 준비 완료로 표시하지 않는다. 각 실제 파일·해시·구도 참조 프레임 번호·이미지 프롬프트·승인 여부를 기록한다. 전송용 변환본이 있으면 원본과 전송본을 구분한다.

| 제외 | 경쟁사 참조 영상, V2 요청의 video 입력, 기존 D/V1 기각 이미지 |
| 길이 | 컷당 `duration:4`로 요청했다. shot02 V4 재시도로 완료했고 추가 요청 없음. 실제 길이는 디코딩 기록 참조 |
| 화면 | `resolution:"720p"`, `aspect_ratio:"16:9"` |
| 소리 | `generate_audio:false`, 참조 오디오 없음 |
| 내부 전환 | 각 4초 클립 안에서 컷/디졸브/장면 전환 없음 |
| 카메라 | 컷 1·2는 참조처럼 안정적, 컷 3은 작은 위쪽 따라 움직임만 |
| 기록 | 컷별 정확한 프롬프트·파라미터·이미지 해시·seed·예측 ID·상태·비용 |

실제 라이브 스키마의 first-frame 필드를 확인하고 참조 이미지/영상 모드와 임의 혼합하지 않는다. 현재 실행 프롬프트는 컷별로 별도 저장하고 ledger에서 그 파일을 연결한다. `42-reference-motion-v2.*`는 역사 기록이므로 현재 요청에 그대로 사용하지 않는다.

같은 seed가 바이트 동일 출력을 보장하지 않는다. 재현 기록은 입력·동작·선택 이유를 복원하기 위한 것이다.

## 5. 컷별 프롬프트 구성

첫 줄에 해당 이미지의 동화 제품·그릇·분량·실제 질감을 유지하도록 명시하고 아래 동작 **하나의 연속 과정**만 지시한다. 나머지 컷 설명을 한 요청에 붙이지 않는다.

1. **컷 1**: 나무 스푼이 중앙 국물에 닿도록 내려가고, 기존의 소량의 불규칙 순두부를 접촉 상태에서 놓은 후 빈 스푼이 우상단으로 빠진다. 처음부터 충분히 가까운 위치에서 시작해 최종 약 1.42초 구간 안에 자연스러운 내려놓기 과정이 담기도록 설계한다. 시간 때문에 실제 움직임이 부자연스러워지면 입력/동작부터 고친다.
2. **컷 2 V4**: 스푼 머리를 대부분 잠긴 채 같은 깊이에 유지하고 처음 약 2.6초에 한 번의 작은 연속 수평 C형 젓기를 한다. 앞쪽 중앙→중앙 왼쪽→중앙을 지나 오른쪽으로 이동하며 기존 순두부를 접촉으로 밀고 접는다. 들어 올리기·스푼 뒤집기·퍼 올리기·빼기·공중 복귀를 하지 않는다. 멈춘 뒤에도 잠긴 상태로 남고 두 번째 동작은 없다. [실제 제출 원문](prompts/42-shot02-stir-v4.json)을 기준으로 검수한다.
3. **컷 3**: V3 `[44,88)`의 깨끗한 추가 리프트+홀드를 합성에서 검수해 최종 채택했다. 이미 분리된 시작이라도 실제 추가 리프트가 읽히면 허용하며, 액체 실이 있는 첫 분리 순간을 포함할 필요는 없다. V4 예비 입력은 한 입이 흐를 국물 웅덩이 없이 지지되고 수저 밑면과 국물 사이 공기 틈이 처음부터 있는 상태로 작은 리프트를 하는 대안이다. 이 예비 프롬프트로 영상 API를 호출한 상태는 아니다.

공통 필수 조건: 새 재료 없음, 부드럽고 불규칙한 실제 순두부와 원본 해상 수준 유지, 안정된 도구/그릇, off-heat, **김·기포·끓음·거품·방울·액체 실·낙하·튀김·파문 없음**, 컷 내부 장면 전환 없음, 문자·로고·소리 없음.

생성 4초 전체를 짧게 가속해 목표 시간을 맞추지 않는다. 동작이 맞는 자연속도 구간을 선택한다. 필요한 과정이 짧은 구간에 없으면 약한 클립을 억지로 채택하지 않는다.

### V3에서 확인한 실패 원인과 V4 대응

V3 shot02/shot03에는 방울·액체 실을 금지하는 문장이 있었지만 실제 액체 효과가 생겼다. 따라서 부정 문구를 더 길게 쓰는 것만으로 방지가 보장되지 않는다. **출발 자세와 이동 경로에서 젖은 수저가 국물 밖으로 나왔다가 되돌아가는 상황 자체를 줄여야 한다.**

- shot02: 스푼을 깊이 유지한 채 수평으로만 움직이고 잠긴 상태에서 멈춘다. 공중에 나온 빈 스푼의 복귀 동작을 없앤다.
- shot03: 이미 확보한 깨끗한 리프트의 이어지는 부분만 선택할 수 있다. 재생성 대안이 필요하면 낮게 분리된 지지 상태에서 시작해 국물 경계 통과를 요구하지 않는다.
- 이는 방울 금지를 완화한 것이 아니다. 모든 선택 프레임에서 액체 실·낙하·착수 돌기·파문은 여전히 FAIL이며, 속도 변경이나 보간으로 숨기지 않는다.
- V4 shot02는 출발 이미지의 잠김 상태와 동작 경로를 함께 바꾼 구현 수정이다. 이를 한 변수만의 인과 실험이나 수치로 입증된 실패율 개선이라고 주장하지 않는다.

1. [최신 사용자 수정사항](LATEST_USER_STEERING.md), 기존 지침 감사, V1/V2 기각 사유를 읽는다.

3. 검수를 통과한 이미지에만 해당 컷의 I2V 요청을 연결한다. 통과하지 않은 이미지를 영상 모델이 고칠 것이라고 기대하지 않는다.

6. 컷별 예측 ID를 확보하고 중복 생성을 피한다. 응답이 모호하면 기존 예측부터 조회한다.

각 시도는 `attempt-001`처럼 고유하게 구분한다. 같은 파일을 덮어쓰지 않는다. 아래 항목을 하나의 시도 기록에 연결한다.

| 범주 | 필수 항목 |

| 목적 | product_no=42, 이 시도의 목표, 앞 시도 대비 변경 내용. V1→V2와 V2→V3 전략 변경은 한 변수 실험과 구분 |
| 입력 | 실제 사진, 새 컷별 시작 이미지, 구도 참조 프레임의 경로/해시/역할, 해당 I2V 입력과 전송본 |

### 비용 기록 예

V1의 단일 6초 요청과 V2의 참조 영상 요청 비용을 현재 3×4초 I2V 총비용으로 재사용하지 않는다. 현재 입력 모드의 공식 단가와 과금 기준을 확인해 3개 요청 및 재시도별로 계산한다. 실제 청구가 확인되지 않았으면 예상치와 구분한다. 이미지 제작 비용도 별도 기록한다.

실행 당시 모델 가격·입력 유형이 다르면 그 값을 다시 확인한다. 참조 영상을 추가하면 `video_in` 조건이 될 수 있으므로 같은 단가를 적용하지 않는다. 공식 가격과 실제 청구를 확인하지 못하면 ‘미확인’으로 남긴다.

## 8. 생성 후 검수 순서

### A. 파일과 시간

- 디코더로 실제 파일을 열어 길이·크기·프레임수·fps·오디오 유무를 확인한다.
- 장면검출은 후보 전환점을 찾는 보조 수단이다. 끓음·스푼 움직임을 컷으로 오인할 수 있으므로 눈으로 확인한다.
- 검출 경계 앞뒤의 인접 프레임을 확인해 디졸브·형태 변형·중간 합성 프레임이 없는지 본다.
- 장면 1과 2, 2와 3의 경계를 실제 PTS 또는 프레임 번호로 기록한다.

### B. 전체 재생 두 번

1. 원속도 1.0×: 첫인상, 장면 역할, 컷 리듬, 테이블 맥락, 마지막 한 입이 읽히는지 본다.
2. 0.5×: 손·도구·그릇·건더기·국물의 연결과 순간 왜곡을 찾는다. 보간 프레임으로 결과를 매끈하게 만들어 검수하지 않는다.

Contact sheet만 보고 전체 통과를 선언하지 않는다. 느린 재생만 보고 먹음직스럽다고 선언하지도 않는다. 각 검수의 목적이 다르다.

### C. 정지 프레임과 원본 비교

장면별 시작·중간·끝, 두 컷 경계 앞뒤, 의심 구간을 실제 제품 사진과 비교한다. 실제의 불규칙한 잔조각과 AI가 반복한 균일한 구슬/쌀알/돌기를 구분한다. 큰 부드러운 면·잠긴 경계·해상되지 않은 부분까지 비교하며, 실제 잔조각이 있다는 이유로 규칙적 과선명 미세 패턴을 통과시키지 않는다.

### D. 게시용 변환본 검수

MP4 원본에서 통과한 후보만 변환한다. 게시용 애니메이션의 프레임, 길이, 루프, 색, 파일 크기와 모바일 실제 표시를 다시 검수한다. 원본 통과는 변환본 통과를 뜻하지 않는다.

## 9. 실패 유형별 한 변수 재시도

V1→V2는 사용자 정정, V2→V3는 경쟁사 음식 복사 실패에 따른 입력 전략 변경이며 한 변수 실험이 아니다. 이 변경을 특정 한 요소의 효과로 주장하지 않는다. 같은 컷별 I2V 전략 안의 재시도에서는 결함이 있는 컷의 변수 한 가지만 바꾼다. 이미 통과한 다른 컷을 다시 생성하지 않는다. 모델·프롬프트·시드·이미지·길이·해상도를 동시에 바꿔 원인을 잃지 않는다. 여러 실패가 보이면 제품 정체성 → 구조 → 물리적 동작 → 미학 순으로 우선한다.

| 실패 | 우선 대응 | 유지할 것 |
|---|---|---|
| 반복 구슬/쌀알/돌기, 과선명 입자, 매끈한 큐브, 새 재료 | 새 시작 이미지가 실제 제품 검수를 통과했는지 확인. 이미지가 실패하면 영상 재시도보다 해당 이미지부터 수정 | 다른 컷·모델·길이·시드 |
| 단일 I2V 클립 내부에 불필요한 컷 발생 | 해당 컷만 다시 검토하고 연속 동작/내부 전환 금지 표현을 조정 | 다른 두 컷과 제품 |
| 클립 내부 음식/냄비가 녹으며 바뀜 | 해당 클립의 입력과 동작을 검토하고 그 컷만 수정. 편집 경계의 모핑이면 전환 효과를 제거 | 다른 두 컷·제품·직접 컷 편집 |
| 국물이 시럽처럼 늘어짐, 방울/액체 실 발생 | 금지 위반으로 기각. 한 입 지지/스푼 기울기 관련 표현만 조정하며 실제 들어올리기 동작은 유지 | 음식·그릇·3컷 동작 순서 |
| 김·기포·끓음·거품·큰 파도 | 금지 위반으로 기각. 새 시작 이미지에 이미 금지 물성이 있는지 확인하고 off-heat 금지 조건을 한 변수로 강화 | 조명·구도·참조·시드 |
| 숟가락·손이 변형됨 | 한 컷의 도구 이동량·동작 수만 줄임. 필요하면 손 노출을 줄이는 해당 기준 구도 수정 | 다른 컷과 제품 |
| 컷 2가 정지 확대/축소이며 젓기 없음 | 쿠캣 실제 원본의 같은 방향/약간 넓은 구도와 밀고 접는 동작을 복원. 새로운 상차림은 발명하지 않음 | 컷 1·3, 실제 제품 |
| 제품이 어둡거나 하이라이트가 날아감 | 해당 기준 이미지의 노출·빛 표현만 수정 | 식재료·행동·타이밍 |
| 같은 설정에서 우연한 작은 결함만 발생 | 시드만 변경하는 탐색을 별도 시도로 기록 | 모든 나머지 요청값 |

각 실패를 단순히 ‘별로임’으로 기록하지 않는다. 예: ‘2.7초 오른쪽 스푼의 손잡이가 두 갈래로 갈라짐’, ‘4.1초 컷 전환에서 그릇 테두리가 다른 모양으로 녹음’, ‘컷 2에도 테이블이 없고 전경 스푼이 그대로임’처럼 위치와 현상을 기록한다.

시도 수가 적은 상태에서 ‘실패율 90% 감소’ 같은 수치를 사용하지 않는다. 반복 샘플이 생기면 전체 시도 수, 같은 조건 여부, 실패 정의, 성공 수를 함께 제시한다. 다른 상품·다른 모델의 성공을 이번 42번 성공으로 합산하지 않는다.

## 10. 적용한 컷별 편집 절차

1. 각 4초 원본을 정상 디코딩하고 실제 fps·길이·프레임수를 기록한다. 컷별 원본과 최종 마스터를 덮어쓰지 않는다.
2. 각 컷을 원속도/0.5×로 보고 전체 동작과 결함을 확인한다. 시작 이미지 통과가 영상 통과를 뜻하지 않는다.
3. 실제 fps가 모두 24라면 컷별 자연스러운 34/63/44프레임 구간을 선택한다. 각 `start_frame`은 0부터 세고 `end_frame`은 제외 경계로 기록해 `end-start`가 각각 프레임수와 같게 한다. 실제 PTS도 병기한다.
4. 컷 1은 내려놓기와 빈 스푼 회수, 컷 2는 실제 잠긴 젓기, 컷 3은 실제 추가 리프트와 짧은 홀드가 선택 구간에 들어 있어야 한다. 컷 3은 깨끗한 이어지는 리프트를 선택할 수 있으므로 처음 분리 순간을 반드시 포함하지 않는다. 단순 홀드만이거나 시간만 맞고 동작이 약하면 선택하지 않는다.
5. 세 구간을 직접 컷으로 연결한다. 원속도를 유지하고 보간·AI 프레임 추가·역재생·강한 속도 압축·새 전환 효과를 사용하지 않는다. 24fps 원본을 23.976fps로 재해석해 0.1% 차이를 맞추려 하지 않는다.
6. 최종 141프레임, 5.875초와 1.416667/4.041667초 컷을 검증한다. fps가 다르면 원본 실제 PTS에 맞춘 편집값을 새로 산출하고 그 이유를 기록한다.
7. 선택 구간이 충분히 좋지 않으면 해당 컷의 입력/동작만 수정한다. 길이를 채우기 위해 정지 프레임이나 약한 행동을 끼우지 않는다.

쿠캣은 비교 자료로만 보며 경쟁사 프레임이나 음원을 최종 파일에 합성하지 않는다.

## 11. 시간·해상도·파일 기준

- 현재 목표는 참조와 가까운 약 6초다. 24fps 확인 시 34+63+44=141프레임, 5.875초를 사용한다. 원본 생성 클립은 각각 4초 요청이며 실제 출력 길이를 따로 기록한다. 6.000초를 강제로 맞추지 않는다.
- 24fps 편집 경계는 1.416667초와 4.041667초다. 쿠캣 실측 1.418083초와 4.045708초에 가깝다. 다른 fps이나 자연스러운 동작 구간에 따른 변경은 실제 PTS·차이·편집 판단으로 기록한다. 초기 ±0.25초는 충실한 동작/리듬이 있을 때 검토 가능한 범위이며 시간 때문에 약한 클립을 채택하는 근거가 아니다.
- 허용 범위를 벗어나거나 리듬에 문제가 있으면 먼저 실제 동작을 훼손하지 않는 트리밍·재편집 가능성을 검토한다. 정확한 프레임 경계가 필요할 때는 후편집으로 맞추고 사용한 PTS를 기록한다. 의미 없는 시간 정밀도 때문에 유료 재생성을 반복하지 않는다. 장면 제어 자체가 실패한 경우에 컷별 생성으로 전환한다. 모델이 낸 타이밍을 확인 없이 계획값으로 기록하지 않는다.
- 로컬 보관용 MP4 마스터는 1280×720, 16:9, 정상 디코딩 가능한 영상으로 남긴다. 전달용 무음 마스터는 오디오 스트림이 없는 상태를 우선한다.
- 오디오가 붙어 나왔다면 파일에 음성·음악이 없는지 추정하지 말고 스트림을 확인해 제거 여부를 기록한다. `generate_audio:false` 요청만으로 무음을 검증했다고 표시하지 않는다.
- 검수에서 보간·AI 프레임 생성·역재생으로 오류를 숨기지 않는다. 이미지 한 장에 팬·줌만 준 영상은 이번 요구의 대체물이 아니다.

## 12. Cafe24 게시용 파생 파일

MP4는 로컬 마스터로 보관한다. Cafe24 디자인 FTP에는 현재 계정에서 허용된 이미지 확장자만 사용한다. 웹FTP와 디자인FTP를 같은 서비스로 가정하지 않고, 현재 관리자 안내·실제 허용 목록을 확인한다.

30MB 미만은 이번 프로젝트가 정한 게시용 용량 기준이다. 공식 안내에서 이 계정의 정확한 서버 제한을 별도로 확인하기 전에는 이를 Cafe24 공식 제한이라고 표현하지 않는다. 더 낮은 서버 제한이 확인되면 그 제한도 함께 충족한다.

게시용은 애니메이션 WebP 또는 GIF를 우선 검토하되, **WebP가 현재 디자인 FTP 허용 확장자에 포함된 경우에만 WebP를 선택**한다. 허용 여부가 불명확하거나 거부되면 허용된 GIF로 전환한다. MP4의 확장자를 이미지 확장자로 바꾸는 방식은 사용하지 않는다.

| 검증 항목 | 방법과 기준 |
|---|---|
| 크기 | 프로젝트 게시용 용량 상한으로 실제 파일 30,000,000바이트 미만을 적용한다. Cafe24의 공식 서버 제한으로 확인한 값은 아니다. 인코더의 예상치나 탐색기 반올림만 사용하지 않는다. |
| 형식 | 확장자뿐 아니라 실제 파일 시그니처·디코더 형식을 확인한다. |
| 애니메이션 | 실제 프레임수가 1보다 큰지 확인하고, 여러 시점의 디코딩 프레임이 다름을 확인한다. |
| 길이 | 프레임 지연시간 합과 실제 재생을 확인한다. GIF의 시간 단위 제약 때문에 마스터와 어긋나면 총합을 보정하고 기록한다. |
| 루프 | 파일의 실제 반복 설정과 브라우저의 두 번 이상 재생을 확인한다. 예전에 사용한 `loop` 플래그가 있었다는 이유만으로 통과시키지 않는다. |
| 화면 | 16:9 유지, 음식과 스푼 잘림 없음, 색·두부 입자·국물 하이라이트가 손상되지 않음. |
| 용량 조정 | 폭·프레임레이트·팔레트/압축 품질 중 한 번에 하나를 바꾸고 시각 손실을 비교한다. |

용량을 낮출 때는 모바일에서 읽히는 질감과 컷 리듬을 우선한다. 낮은 프레임레이트로 숟가락이 뛰거나 GIF 팔레트가 국물의 색을 얼룩으로 만들면 압축 성공이 아니라 검수 실패다. 특정 인코딩 플래그의 존재를 결과 파일의 실제 속성 검증으로 대신하지 않는다.

## 13. 상품 상세 슬라이더 반영 조건

이 절은 게시를 실제 진행할 때의 조건이며 이 문서 작성 자체가 게시 완료를 뜻하지 않는다.

- 원본 히어로와 기존 슬라이드 순서를 보존하고 새 비교 후보를 추가한다. 기존 후보를 조용히 교체·덮어쓰지 않는다.
- 현재 상품 상세 슬라이더의 크기, 여백, 전환 조작, 테두리 및 모바일 배치를 따른다.
- 후보 표시는 **오른쪽 아래 작은 숫자**로 현재 슬라이더의 번호 규칙에 맞춘다. 파일명·생성 모델·작업 폴더·A/B 내부 코드 등을 고객용 이미지 위에 표시하지 않는다.
- 숫자 라벨은 음식의 중요한 부분을 가리지 않게 하고 현재 UI와 일관된 위치·크기로 둔다. 사용자에게 보일 제품 카피를 임의로 새로 쓰지 않는다.
- 업로드 후 반환 URL이 열리는지, 이미지 형식과 크기가 맞는지, PC·모바일에서 3컷과 루프가 실제 재생되는지 확인한다.
- 원본 슬라이드와 나머지 상품 내용이 유지됐는지 전후를 비교한다. 상품 정보 전체를 불필요하게 재작성하지 않는다.
- 로컬 파일 성공, FTP 전송 성공, 상세페이지 반영 성공, 사용자 시각 승인 상태를 각각 구분해 기록한다.

## 14. 이후 다른 음식에 확장할 때

42번 결과의 장면 구성과 검수 방식을 재사용하되 재료 묘사는 재사용하지 않는다. 다음 상품마다 실제 원본을 다시 확인하고 제품별 질감·액체 성질·조리/섭취 동작을 새로 정의한다.

- 공통으로 옮길 것: 장면 역할, 짧고 읽히는 동작, 컷별 거리 차이, 메타데이터와 비용 기록, 한 변수 재시도, 1.0×/0.5× 검수.
- 다시 판단할 것: 건더기, 소스 점도, 허용되는 뜨기/찢기/젓기 동작, 그릇·식기, 실제 분량과 고명.
- 옮기지 않을 것: 순두부 입자 문구, 국물 움직임 수치, 다른 제품의 재료, 42번에서만 맞는 스푼 한 입.
- 새 상품으로의 실행은 별도 작업 범위가 확인된 뒤 진행한다. 이번 42번 요청을 다른 상품 일괄 생성으로 확대하지 않는다.
