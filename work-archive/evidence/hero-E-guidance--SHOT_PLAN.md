## 목표와 적용한 방식

동화가든 42번 실제 음식을 유지하면서 쿠캣 상세본문 첫 영상의 구도·수저 동작·길이를 매우 가깝게 따른다. 최종은 약 6초, 3장면, 2번의 직접 컷이다. 새 액션·증기·방울·상차림을 발명하지 않는다.

기본 경로는 검수된 시작 이미지의 컷별 4초 I2V와 원속도 편집이다. **V3 shot01 `[22,56)`, V4 shot02 `[8,71)`, V3 shot03 `[44,88)`을 채택해 완료**했다. 한 번의 영상 요청에 3컷과 음식 교체를 다시 맡기지 않는다.

사용자가 가까운 구도 재현과 V2 영상 참조를 허용했으나 V2에서 경쟁사 음식이 따라 들어왔다. 최종 컷별 I2V에서 경쟁사 영상을 제외한 것은 그 실패에 대한 기술적 대응이다. 쿠캣 영상은 로컬 비교 자료로 남고, 경쟁사 프레임이나 음원을 완성 파일에 삽입하지 않는다.

## 새 시작 이미지 검수

[V3 이미지 요청](prompts/v3-keyframe-prompts.json)은 실제 제품 사진과 쿠캣의 해당 시작 프레임을 사용했다. 현재 shot02 V4는 [잠긴 수저 이미지 기록](generation/keyframes-v4/shot02-manifest.json)을 따른다. 실제 사진은 음식 사실, 쿠캣 프레임은 구도·수저 위치의 근거다. 기존 D 후보·V1의 반복 입자 이미지·V2의 경쟁사 음식 이미지는 사용하지 않는다.

1. 실제 사진의 황동 그릇·붉은 주황 국물·분량·기존 재료를 확인한다.
2. 순두부의 크기 다른 넓은 찢김면, 젖고 무너진 경계, 작은 잔조각, 국물 틈과 부분 잠김을 비교한다. 반복 구슬·쌀알·사슬·콜리플라워 돌기·새로 선명해진 미세 노이즈는 기각한다.
3. 실제 잔조각을 지우려고 큐브·공·젤·퓨레로 만들지 않는다. 원본에서 부드러운 부분은 부드럽게 남긴다.
4. 컷 1의 접촉 직전, 컷 2의 대부분 잠긴 스푼 출발 상태를 확인한다. 컷 3은 현재 깨끗한 추가 리프트 구간을 우선하며, 예비 이미지를 쓸 경우 낮게 분리된 지지 상태와 깨끗한 수저 밑면/공기 틈을 확인한다.
5. 김·연무·기포·끓음·거품·방울·액체 실·낙하·튀김·동심원 파문·추가 재료가 없어야 한다.

생성된 파일을 아직 검수하지 않았다면 NOT_CHECKED다. 시작 이미지 검수 전에는 해당 I2V를 실행하지 않는다.

## V4 shot02의 정확한 동작과 교훈

[제출 프롬프트](prompts/42-shot02-stir-v4.json)는 처음부터 스푼 머리를 대부분 국물 아래에 두고 손잡이와 윗 금속 가장자리만 보이게 한다. 첫 약 2.6초에 앞쪽 중앙에서 중앙 왼쪽으로, 이어 중앙을 지나 오른쪽으로 **한 번의 연속 수평 C형 젓기**를 한다. 스푼 깊이를 일정하게 유지하고 내용물만 접촉으로 밀고 접는다. 멈춘 뒤에도 잠긴 채 남는다. 공중 복귀·퍼 올리기·수저 뒤집기·다시 담그기 같은 추가 동작은 없다.

V3의 명시적 금지 문장만으로 액체 실을 막지 못했다. 부정 문구를 강화하는 것 외에 **시작 자세와 움직임 자체가 젖은 수저의 국물 밖 출현을 요구하지 않도록** 바꾼다. shot02는 잠긴 수평 동작, shot03의 미사용 대안은 처음부터 낮게 분리되어 흐를 국물 웅덩이 없이 지지된 한 입이다. 이 변경도 결과 검수를 대신하지 않는다.

shot03의 깨끗한 후반 선택은 합성 재생과 독립 검수를 통과했다. V4 shot03 예비 이미지/JSON은 사용하지 않았으며 이 대안의 영상 API 요청도 없었다.

## 영상 요청과 편집

- 모델 `bytedance/seedance-2.0`, 요청당 4초, 720p, 16:9, `generate_audio:false`. shot02 V4 재시도로 완료했고 추가 제출은 없다.
- 입력은 검수한 해당 시작 이미지 하나의 first-frame I2V 모드다. 현재 라이브 스키마와 단가를 확인한다. 경쟁사 참조 영상은 넣지 않는다.
- 각 클립 내부는 컷이 없는 해당 동작의 연속 과정이다. 최종 2번의 컷은 편집에서 만든다.
- 컷별 정확한 프롬프트·파라미터·이미지 해시·seed·예측 ID·비용·출력 해시를 별도로 저장한다. V2의 `42-reference-motion-v2.*`는 실패 이력이며 현재 요청으로 재사용하지 않는다.
- 전체 4초를 빠르게 압축하지 않고, 원속도에서 필요한 과정을 담은 좋은 구간을 고른다. 목표 길이를 이유로 약한 클립을 채택하지 않는다.

세 출력의 실제 24fps를 유지해 34+63+44프레임을 선택했다. 최종 141프레임/5.875초, 컷 경계 1.416667/4.041667초다. 이는 실제 참조와 약 1.4ms/4.0ms 차이이며 0.1% 속도 재해석으로 없앨 필요가 없다. 6.000초도 강제로 채우지 않는다.

각 사용 구간의 0기준 `start_frame`, 끝 제외 `end_frame`, 실제 시작/끝 PTS와 프레임수를 기록한다. 선택 구간은 처음 프레임부터라고 가정하지 않는다. 컷 1은 접촉/놓기/빈 수저 회수가 읽혀야 한다. 컷 3은 처음 분리 순간이 없어도 깨끗한 실제 추가 리프트+홀드가 읽히면 사용할 수 있다. 금지 효과가 있는 프레임은 단 한 장도 선택에 넣지 않는다. fps가 다르면 실제 PTS에 맞춰 가까운 자연스러운 구간과 경계를 다시 산출한다.

## 실패·검수·게시

V2→V3는 입력 전략 변경이며 V4 shot02는 시작 이미지의 잠김 상태와 수평 동작 경로를 함께 바꾼 결함 대응이다. 이를 한 변수만의 인과 실험이나 수치로 확인된 개선율로 주장하지 않는다. 이후 재시도도 문제가 있는 컷에 한정하고 이미 확보한 다른 컷을 재생성하지 않는다. 이미지 실패를 영상 모델에 맡기지 않는다.

각 클립과 최종 마스터의 전체 1.0×/0.5×, 실제 제품 사진 비교, 컷 경계 인접 프레임을 검수한다. Contact sheet와 정상 디코딩만으로 공개 합격을 선언하지 않는다. [검수표](qa/ACCEPTANCE_CRITERIA.md)의 필수 항목을 실제 증거로 판정하고 합격 마스터만 게시용 애니메이션으로 변환한다.

최종 E-v4는 상품 42의 기본 5/5 후보로 게시되었고 데스크톱·모바일 표시와 이동을 확인했다. 과거 실패 기록은 보존한다. 상세 완료 근거는 [README](README.md), [최종 QA](qa/FINAL_ACCEPTANCE.json), [게시 보고서](deploy/DEPLOYMENT_REPORT.md), [비용 기록](generation/COST_STATUS.json)에 있다.
